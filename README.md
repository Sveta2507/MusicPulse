## 1. Загальна інформація

**UA Music Pulse** — це сучасний вебзастосунок для дослідження української музичної сцени. Він об'єднує дані про гурти й сольних виконавців різних напрямів: рок, поп, електрофолк, хіп-хоп, інді, постпанк, метал та інші жанри.

Програма одержує Open Linked Data з Wikidata за допомогою SPARQL, нормалізує їх, зберігає у SQLite і показує через адаптивний інтерфейс. Дані також доступні через REST API та у семантичному форматі RDF/Turtle.

## 2. Аналіз предметної області

### 2.1. Актуальність

Сучасна українська музична сцена швидко змінюється, охоплює багато жанрів і набуває міжнародної видимості. Відомості про виконавців розміщені на різних платформах і часто мають несумісну структуру. Використання відкритого графа знань дає змогу працювати зі стабільними URI, повторно використовувати дані та явно описувати зв'язки між сутностями.

### 2.2. Мета

Метою проєкту є створення зручного вебкаталогу сучасних українських виконавців на основі Open Linked Data з можливістю пошуку, фільтрації, перегляду детальної інформації та експорту семантичних даних.

### 2.3. Завдання

1. Проаналізувати доступні джерела Open Linked Data для музичної предметної області.
2. Відібрати реальні сутності сучасної української сцени та їхні Wikidata QID.
3. Отримати назви, описи, жанри, роки, зображення та зовнішні посилання через SPARQL.
4. Реалізувати локальне сховище та окремий шар доступу до даних.
5. Створити прикладний шар для оновлення, пошуку, статистики й RDF-експорту.
6. Розробити сучасний адаптивний вебінтерфейс.
7. Додати REST API та експорт RDF/Turtle.
8. Перевірити програму автоматичними тестами.
9. Підготувати UML-діаграми, скриншоти, презентацію та звіт.

### 2.4. Цільова аудиторія

- слухачі, які хочуть відкривати українську музику;
- музичні журналісти та дослідники;

## 3. Постановка задачі

### Вхідні дані

- автоматично розширений перелік із 213 Wikidata QID та кураторським ядром;

- пошук, фільтрація, сортування й агрегація;

## 5. Open Linked Data

### 5.1. Обране джерело

Основним джерелом є [Wikidata](https://www.wikidata.org/) — відкритий багатомовний граф знань. Запити виконуються через [Wikidata Query Service](https://query.wikidata.org/). Дані Wikidata поширюються за ліцензією [CC0 1.0](https://creativecommons.org/publicdomain/zero/1.0/).

Wikidata обрано через такі переваги:

- кожна реальна сутність має стабільний глобальний QID;
- підтримуються RDF і SPARQL;
- доступні багатомовні назви й описи;
- музичні виконавці пов'язані з жанрами, зображеннями та зовнішніми ідентифікаторами;
- дані можна повторно використовувати без створення закритого власного довідника.

### 5.2. Відібрані сутності

Початкове кураторське ядро містить Океан Ельзи, Бумбокс, The Hardkiss, Go_A, ONUKA, ДахаБраха, Kalush Orchestra, alyona alyona, Jerry Heil, KAZKA, Jinjer, IGNEA, 1914, Latexfauna, SadSvit і Vivienne Mort. Для відчуття повноцінного музичного каталогу набір автоматично розширено до **213 сутностей**: **102 гуртів** та **111 сольних виконавців**.

Для розширення вибірки було виконано два оптимізовані SPARQL-запити: окремо для українських музичних гуртів і сучасних українських музикантів. Результати впорядковувалися за кількістю Wikidata sitelinks, тому до вибірки першими потрапили відоміші й краще описані сутності. Початкове кураторське ядро збережено.

Розширений список QID і резервних жанрів розміщено у [`data/seed_artists.json`](data/seed_artists.json). Фактичну відповідь Wikidata з датою отримання та повним SPARQL-запитом збережено у [`data/wikidata_snapshot.json`](data/wikidata_snapshot.json). Для 174 сутностей Wikidata надала зображення, для 182 — рік заснування або народження.

### 5.3. Механізм одержання

Клієнт [`open_data/wikidata_client.py`](open_data/wikidata_client.py) формує один `SELECT`-запит. `VALUES` обмежує результат обраними QID, `OPTIONAL` дає змогу працювати з неповними полями, а мовні фільтри надають перевагу українським та англійським підписам.

Скорочений приклад:

```sparql
PREFIX wd: <http://www.wikidata.org/entity/>
PREFIX wdt: <http://www.wikidata.org/prop/direct/>
PREFIX rdfs: <http://www.w3.org/2000/01/rdf-schema#>

SELECT ?item ?nameUk ?image ?inception ?genre ?genreUk
WHERE {
  VALUES ?item { wd:Q1008489 wd:Q12071385 wd:Q46968169 }
  OPTIONAL { ?item rdfs:label ?nameUk. FILTER(LANG(?nameUk) = "uk") }
  OPTIONAL { ?item wdt:P18 ?image }
  OPTIONAL { ?item wdt:P571 ?inception }
  OPTIONAL {
    ?item wdt:P136 ?genre.
    OPTIONAL { ?genre rdfs:label ?genreUk. FILTER(LANG(?genreUk) = "uk") }
  }
}
```

Якщо зовнішній сервіс тимчасово повертає `429 Too Many Requests` або немає мережі, програма використовує збережений JSON-знімок. Невдале оновлення не видаляє чинні локальні дані.

### 5.4. Семантичний зв'язок

Локальні URI мають форму:

```text
https://svitlana-denysenko.github.io/ua-music/resource/artist/Q12071385
```

Відповідний зовнішній ресурс:

```text
https://www.wikidata.org/wiki/Q12071385
```

Ресурси поєднано предикатом `owl:sameAs`, оскільки локальна картка і Wikidata-ресурс описують того самого реального виконавця.

```turtle
<https://svitlana-denysenko.github.io/ua-music/resource/artist/Q12071385>
    a schema:MusicGroup ;
    schema:name "Jinjer"@uk ;
    schema:genre <https://svitlana-denysenko.github.io/ua-music/resource/genre/Q11366> ;
    owl:sameAs <https://www.wikidata.org/wiki/Q12071385> .
```

RDF-граф використовує словники **Schema.org**, **Dublin Core Terms**, **OWL**, **RDF** і типи **XSD**. Повний результат: [`exports/ukrainian_music.ttl`](exports/ukrainian_music.ttl).

### 5.5. Безпека зовнішніх посилань

Поле Wikidata `P856` не вважається автоматично безпечним. Колишній офіційний домен може прострочитися, перейти до іншого власника та почати перенаправляти на рекламу, казино або інший сторонній ресурс. Саме це сталося з адресою `brunettesshootblondes.org`: у Wikidata зберігався старий домен, а небезпечний URL із піддоменом `ww16` створювався вже зовнішньою системою переадресації.

Тому застосовано політику **safe by default**:

- довільні значення `P856` не завантажуються до snapshot і SQLite;
- такі значення не повертаються REST API;
- кнопка неперевіреного офіційного сайту не створюється в інтерфейсі;
- такі адреси не публікуються як `foaf:homepage` у RDF;
- залишено лише URL, сформовані зі стабільних ідентифікаторів Wikidata, Spotify та YouTube;
- зовнішні переходи відкриваються з `rel="noreferrer"`.

## 6. Архітектура

Застосунок поділено на чотири обов'язкові шари.

| Шар | Реалізація | Відповідальність |
|---|---|---|
| модуль відкритих даних | `open_data/` | SPARQL, Wikidata, нормалізація, snapshot |
| шар доступу до даних | `data_access/` | SQLite, SQL, Repository |
| прикладний шар | `services/` | сценарії, статистика, оновлення, RDF |
| інтерфейсний шар | `routes/`, `templates/`, `static/` | HTML, REST API, CSS, JavaScript |

Браузер звертається до Flask/Waitress через HTTP. Прикладний сервіс читає локальні дані через Repository та за вимогою виконує HTTPS/SPARQL-запит до Wikidata. SQLite, JSON snapshot і Turtle-файл розміщуються на сервері застосунку.

Use-case, компонентна й пакетна діаграми використовують стандартні UML-позначення: акторів, варіанти використання, межу системи, `<<extend>>`, компоненти, пакети та пунктирні залежності.

### 7.5. Схема бази даних

![ER-модель бази даних](docs/diagrams/data_model.png)

- `artists` — основні атрибути виконавців;

## 12. Запуск

### Варіант 1 — одна команда у PowerShell

```powershell
cd project
.\run_all.ps1
```

Скрипт створює середовище за потреби, встановлює залежності, ініціалізує дані, запускає тести і відкриває сервер за адресою <http://127.0.0.1:5000>.

Якщо PowerShell блокує локальні скрипти, для поточного процесу можна виконати:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\run_all.ps1
```

### Варіант 2 — покроково

```powershell
cd project
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python scripts\bootstrap.py
python -m pytest --cov=. --cov-report=term-missing --cov-report=html:htmlcov
waitress-serve --host=127.0.0.1 --port=5000 app:app
```

Після запуску відкрити <http://127.0.0.1:5000>.

### Оновлення живих даних

У вебінтерфейсі натиснути **«Оновити дані»** або виконати:

```powershell
Invoke-RestMethod -Method Post http://127.0.0.1:5000/api/refresh
```

Якщо Wikidata обмежує частоту звернень кодом `429`, слід зачекати й повторити пізніше. Для демонстрації застосунок продовжує працювати з локальним snapshot.

## 16. Висновки

У межах індивідуального проєкту створено повноцінний чотиришаровий вебзастосунок, який перетворює Open Linked Data на практичний музичний каталог. Wikidata використовується не лише як зовнішнє посилання, а як фактичне джерело структурованих сутностей і зв'язків. SQLite та JSON snapshot забезпечують швидкість і автономність, а RDF/Turtle робить результати придатними для повторного семантичного використання.

Практичний результат підтверджено 20 автоматичними тестами з покриттям 83%. Застосунок містить **213 реальних музичних сутностей**, **121 жанр** і створює **2318 RDF-трійок**. Сім професійних PlantUML-діаграм доступні одночасно у вихідному, векторному та растровому форматах. Окремі тести гарантують, що неперевірені домени не потрапляють до API та RDF. Подальший розвиток може охоплювати музичні релізи, події, географію локальних сцен та персональні рекомендації.
